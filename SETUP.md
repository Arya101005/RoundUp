# SETUP

Steps that require a human (MASTER_SPEC section 22), with exact commands.

## 1. Supabase project

1. Create a project at https://supabase.com/dashboard.
2. Under **Authentication → Providers**, enable **Anonymous sign-ins**.

## 2. Link and push the schema

```bash
npm install -g supabase   # if you do not have the CLI yet
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase db push
```

Migrations 0001-0009 create tables, RLS policies, helper functions, the realtime
publication, and the `pg_cron` jobs. Extensions (`pgcrypto`, `pg_trgm`, `vector`,
`pg_cron`, `pg_net`) are enabled by the migrations where permitted; if `pg_cron` or
`pg_net` are off for your plan, enable them in the dashboard and re-run
`supabase db reset`-style migration `0009`.

Then register the cron callback URL (one-time, stored in Vault):

```sql
select vault.create_secret('https://YOUR_PROJECT.supabase.co', 'app_url', 'Base URL for cron HTTP calls');
```

(The `cron_secret` is generated by migration 0009 itself; you never need its value.)

## 3. Function secrets

```bash
supabase secrets set \
  SUPABASE_SERVICE_ROLE_KEY=... \
  ALLOWED_ORIGINS=https://your-domain.example,http://localhost:5173 \
  AI_PROVIDER=openai-compatible \
  AI_BASE_URL=https://openrouter.ai/api/v1 \
  AI_API_KEY=... \
  AI_MODEL=...
```

AI is optional: with no key the content pipeline falls back to cache -> external ->
seed, and post-game analysis uses the rules-based "Automated analysis".

## 4. Deploy functions

```bash
supabase functions deploy create-room join-room leave-room update-room send-chat get-snapshot
# later phases: start-game game-action game-tick prepare-content evaluate sweeper
```

## 5. Frontend

```bash
cp .env.example .env   # fill VITE_SUPABASE_URL, VITE_SUPABASE_PUBLISHABLE_KEY, VITE_APP_URL
npm run build
```

Deploy the `dist/` folder to Vercel or Cloudflare Pages with an SPA rewrite to
`/index.html`. Set only the two `VITE_*` Supabase values there, then add the production
URL to Supabase **Authentication → URL Configuration** and to `ALLOWED_ORIGINS`.

`.env` is gitignored; only `.env.example` is committed. The service role key and AI keys
exist exclusively as Edge Function secrets - never in `VITE_*` variables.

## 6. Tests that need infrastructure

```bash
npx supabase start        # local stack (requires Docker)
npm run test:integration  # bot harness plays full games (Phase 3+)
npm run test:e2e          # Playwright, 3 browser contexts
```
